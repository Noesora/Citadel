Architecture · capture and promotion

Capture lands in a Node

Approved capture roots and session hooks send work to a seat's Node. Governed promotion is a separate path into Central.

01 · Capture

Hooks write to the seat Node

Capture is configured on the machine and uses the seat's access token. Git capture runs only in an Approved Capture Root. The SessionEnd hook sends a short session note to the configured Node.

Git pre-push hook

The hook snapshots pushed commits in an approved root and sends them to the Node. A missing or unmatched root skips capture.

SessionEnd hook

The client distills a short note from the session transcript and posts it to the Node. It does not share a Shared Session Trace.

  • Capture roots are selected during `citadel setup` or `citadel onboard`.
  • Hooks send writes through the configured HTTPS Node endpoint.
  • Hook failures do not block a git push or session close. A receipt can report an unconfirmed send.
02 · Governed sharing

Promotion is a separate decision

A capture stays on its Node unless a governed process creates a separate copy in Central. Seat capture cannot route a write directly to Central.

Review candidate

The promotion policy checks for secrets, capture-root tags, source references, and whether content is relevant and safe to share.

Choose the route

Eligible organization work can be copied to Central. A new project can wait for approval. Other material stays on the Node.

01

The copy keeps its origin

Promotion adds a governed copy. The original remains in the seat's Node, and the Central record carries promotion metadata.

02

Shared traces follow another rule

A person can volunteer a trace through citadel_share_session. Shared traces stay reference-only and do not enter Central promotion.
