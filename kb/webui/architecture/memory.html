Architecture · memory and sharing

Three memory scopes

Citadel keeps seat memory, curated organization knowledge, and volunteered session traces in separate scopes.

System mapMemory and sharingCapture and promotionSelf-hosting
01 · Private working memory

A Node belongs to a seat

A Node is the default target for a seat's working notes and capture. A seat-scoped caller can read its own Node and Central when its token permits those reads.

Seat scope

The Node is the storage boundary. A normal seat token cannot read another seat's Node. A token's role and allowed datasets still control each request.

Privileged access

Admin and service identities can have broader access, with audit. Node isolation does not mean an operator can never inspect a Node.

02 · Shared organization memory

Central has a governed write path

Central is the organization-wide dataset. Seat-scoped callers read it under their token scope, but seat capture does not write directly into it.

  • Organization sync can add source material to Central.
  • A separate promotion process can copy eligible material from a Node.
  • The original stays on the Node when a promotion creates a Central copy.
03 · Voluntary sharing

A Shared Session Trace stays separate

A Session Trace records a task, approaches, dead ends, and files touched. It is a reference to prior work, not a claim that the result is true.

Explicit share action

The author chooses to share through citadel_share_session. SessionEnd capture does not auto-share a trace.

Separate dataset

Shared traces live in session-traces, outside both Node and Central. Search marks them as reference-only. They are not promoted into Central.

Search resolves its scope from the caller's role and token. Results include a dataset and source locator when the retained record has that information. Treat retrieved content as material to check, including content from Central.

Read the Node and Central decision, the Shared Session Trace decision, and the agent access model.
